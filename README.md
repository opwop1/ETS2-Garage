# 欧卡2 车辆配件搭配助手 · ETS2 Garage

读取《欧洲卡车模拟2》安装目录里的**全部 .scs 归档**，解析出所有车辆模型与配件定义，
让你把**任意车辆的配件装到任意车辆上**自由混搭，实时 3D 预览，并给出每个配件的
**挂点 locator 名称 + XYZ 坐标 + 旋转四元数 + 缩放**，方便写入存档或做成 mod。

界面为中文（自动读取游戏内 `locale/zh_cn` 文本），单文件 exe，不需要安装任何东西。

---

## 快速开始

### 方式一：直接运行打包好的 exe

```
dist\ETS2Garage.exe
```

1. 启动后选择（或粘贴）游戏安装目录，例如
   `D:\SteamLibrary\steamapps\common\Euro Truck Simulator 2`
2. 点「开始扫描并解包」——首次约 10~40 秒（只读归档目录表，不解压全部内容）
3. 左侧选车 → 中间 3D 预览 → 右侧点槽位换配件 → 底部看坐标表

程序会记住游戏路径，下次启动自动扫描。

#### 窗口生命周期（这块很容易做错）

exe 内部是一个本地 HTTP 服务 + 一个浏览器窗口，两者谁先谁后必须小心处理：

* Chromium 的 `--app=URL` **不保证自己开窗口**：如果该配置目录已经被 Edge/Chrome
  占用（Edge 关窗后仍会驻留后台进程），新的 `msedge.exe` 会把网址**交给已有进程然后
  立刻退出**。所以**不能拿启动器进程的存活当"窗口还开着"的判断依据**——一旦这么做，
  程序会在你只是安静看模型的时候就自杀，表现为"点车辆列表没反应 + 连接被拒绝"。
* 现在的做法：前端每 5 秒 `fetch('/api/ping')`；启动器只有在
  **「我们自己拉起的浏览器进程存活超过 10 秒之后才退出」**（说明窗口确实是它的）
  才立即收工，否则退回到**静默 120 秒**的超时判断（这个值同时要大于浏览器对隐藏/
  最小化窗口的定时器节流间隔 ~60 秒，否则最小化就会被误杀）。
* 端口被占用时自动换端口重试；`/api/ping` 之外任何请求都会刷新活跃时间。

### 方式二：从源码运行

```bat
python ets2garage\app.py
```

依赖：Python 3.11+、`pillow`、`numpy`、`pywebview`（可选）。
`native/out/gdeflate.dll` 是贴图解码所需的本地库，仓库内已包含。

### 方式三：只开网页服务（浏览器里用）

```bat
python ets2garage\server.py 8765
```

然后浏览器打开 http://127.0.0.1:8765/

## 功能

| 功能 | 说明 |
| --- | --- |
| 全量车辆 | 26 款卡车 + 58 款挂车（含全部 DLC 与 mod，自动识别） |
| 全量配件 | 跨车辆汇总，例如「beacon」槽位可选出 **283** 个来自不同品牌的配件 |
| 自由混搭 | 槽位不校验 `suitable_for`，任意品牌的配件都能装到任意车辆上 |
| **载入原厂配置** | 选车后自动装出游戏里那台**素车**：`data.sii` + **驾驶室/底盘各自的 `defaults[]`**（Scania S 2016 共 20 项，含油箱、后挡泥板、底盘护罩、拖车线束、侧裙、后视镜…） |
| 3D 预览 | 真实 PMG 几何 + PMD 材质 + GDeflate 解压的**真实贴图**，可旋转缩放 |
| **涂装** | 1200+ 涂装可选（按驾驶室过滤）；实色涂装显示真实颜色，**花纹涂装按掩码渲染**，还支持游戏里的**配色 1/2/3/4** 切换 |
| **自定义车漆** | 选 `color0`（自定义颜色）这类涂装时会出调色板，改颜色整车即时变色 |
| **自由调位置** | 选中**配件**后用 3D 箭头拖动（移动/旋转/缩放），或用数值框与 ± 按钮微调，实时显示最终坐标 |
| **车壳锁定** | 驾驶室 / 车身 / 底盘是最基本的壳，**不可选中、不可移动**，只作为坐标基准 |
| **贴到表面** | 一键把悬空的配件下落到模型表面 |
| 挂点可视化 | 模型里所有 locator 以小球显示，鼠标悬停即显示名称与 XYZ |
| 坐标表 | 挂点基座 XYZ / 手动偏移 XYZ / **最终世界坐标 XYZ** / 旋转 / 缩放 |
| 导出 | CSV、JSON、一键复制全部坐标（含偏移与最终坐标） |
| 挂点检查 | 若目标车辆模型没有对应挂点会明确提示（配件落在原点，需手动放置） |

### 载入原厂配置（游戏里的"素车"）

选车时会自动装出游戏购买车辆时看到的那台完整素车：

* **`defaults[]`**（新车使用）：厂家写死的配件清单，例如 `daf.2021` 15 项、`volvo.fh_2021` 15 项。
* **驾驶室 / 底盘各自的 `defaults[]`**（老车全靠这个）：底盘带**油箱、后挡泥板、底盘护罩、
  拖车线束**，驾驶室带**内饰、涂装、顶灯**——这是之前漏掉的关键来源。
* **车轮**：`f_tire / f_disc / f_hub / f_nuts / r_*` 的定义是**全局共享**的
  （`def/vehicle/f_tire/1.sii`，共 10 个槽位、160+ 种轮胎/轮毂/螺母可选），
  挂点在**底盘模型**的 `wheel_f_*` / `wheel_r_*` 上——每个槽位按挂点数量自动装到每个轮位
  （4x2 装前 2 后 2，6x2 会多一对）。之前漏了这一步，所以看着像"只有一个壳"。
* **`fallback[]`**：底盘/驾驶室/发动机/变速箱/涂装等基础件。
* **一个模型里装着一台车的所有配置变体**：`daf_xf/truck.pmg` 同时含 9 种底盘
  （`chs_4x2`/`chs_6x2`/`chs_6x4`/`chs_6x_lng`…）和 6 种驾驶室，每种各带自己的轮位挂点。
  PMD 的 **variant 表**（底盘定义里的 `variant: 'chs_4x2'` 就指向它）说明当前配置该显示哪些
  part。**漏了这一步就会把所有变体的轮子同时画出来**（DAF XF 一个后轮能有 10 个挂点）。
* 隐藏规则必须精确：**只有在别的变体里确实出现过的 part 才算"配置选项"，才允许隐藏**。
  像 `brace_on`/`brace_off`、`cables_on`/`cables_off` 这种任何变体都没标记过的 part 必须保留，
  否则会丢几何。变体名匹配是大小写不敏感的（老车写 `Default`，模型里是 `default`）。
* **挂点名字不一定等于槽位名**：`interior`↔`interior2`、`doorstep`↔`doorsteps`、
  `steering_w`↔`swheel`。匹配要分级（精确 → 强别名 → `槽位_` 前缀 → 槽位+数字 →
  槽位+复数 s → 前缀兜底 → 弱别名），弱别名（如 `ext_interior`，其实是外部视角挂点）
  必须排在最后。**匹配不上就不要渲染**——早期版本把零件画在原点，
  结果驾驶舱内饰从底盘下面伸出来。
* **有些模型所有轮位都叫 `wheel_f_*`**（低平板挂车 6 个，没有 `wheel_r_*`）。单一轴时
  要把它交给"实际装了配件的那个组"，且前后组绝不能同时占用，否则会叠两整套轮子。
* **老车（2012 前）用 `detail_model` 而不是 `model`**，而且 Scania R / DAF XF / Iveco HiWay
  的"驾驶室"和"底盘"指向**同一个 `truck.pmd`**：靠 variant 表分成互补的两半，
  所以两个都要渲染；只有拿不到 variant 信息时才去重。
* **挂点驱动的自动补全**：先按上面的 defaults 装，剩下**凡是车辆模型上真有挂点（locator）
  的槽位**就补上该槽位原厂默认件。因此每一台车都是完整的，且**以后游戏出新车辆也不用改代码**。
* **挂车车轮**在独立目录 `def/vehicle/trailer_wheel/`，已一并支持。
* **非槽位但有模型的部件**（如 `interior` 驾驶舱内饰）也会一并装上。
* 配件类型不再用白名单过滤——SCS 一直在新增
  `accessory_addon_tank_data`、`accessory_addon_trailer_cables_data` 这类专用类型，
  之前用固定列表会把**油箱、拖车线束**整个槽位丢掉。
* **`require[]`** 里必需但厂家没写默认值的槽位 → 自动取**未解锁、最便宜的原厂件**补上。

切换驾驶室或底盘时，会连同它自带的出厂配置一起换（例如 High Roof 和 Normal Roof 的
内饰、顶灯、涂装都不一样）。

右侧顶部有「重新载入原厂配置」和「清空全部配件」两个按钮。

### 涂装

* **实色涂装**（如 MAN 的 `ral_9016`）：直接用涂装的 `base_color` 给车身上色。
* **自定义颜色**（`color0`，`base_color_locked: false`）：界面出现**调色板**，改完整车即时变色。
* **花纹涂装**（`paint_job_mask`）：用自定义着色器按掩码渲染。
  实测结论：掩码用 **UV0**，把调色板下标编码在 **RGB 三个通道**里（黑=色位0、R=色位1、
  G=色位2、B=色位3），配合涂装自带的 `color_variant[]`（每 4 个为一组配色）。
  所以游戏里的**配色 1/2/3/4** 也能切。

### 调整配件位置

外车配件挂上去经常会错位或悬空，所以每个配件都可以单独调整：

1. **选中**：直接点 3D 模型上的**配件**（点空白处取消），或点右侧槽位卡片上的绿色「调整」
   标签，或点底部坐标表的配件行。驾驶室/底盘这类车壳点不动，也不能移动。
2. **拖动**：选中后出现三色箭头（X 红 / Y 绿 / Z 蓝），拖动即可移动。
   按 <kbd>W</kbd> 移动、<kbd>E</kbd> 旋转、<kbd>R</kbd> 缩放切换模式，<kbd>Esc</kbd> 取消选中。
3. **精确微调**：左下角面板有 X/Y/Z、绕 X/Y/Z 轴旋转（度）、缩放输入框，
   以及每项两侧的 −/+ 按钮；「步长」可选 0.001 / 0.01 / 0.05 / 0.1 m。
4. **贴到表面**：配件悬空时点一下，它会自动下落到正下方的模型表面。
5. **读数**：面板实时显示「挂点基座 → 偏移 → 最终坐标」，
   底部坐标表同步显示挂点 XYZ / 偏移 XYZ / **最终 XYZ**（橙色高亮表示已调整）。
6. **重置**：单个配件或一键全部重置。「导出 CSV/JSON」会同时包含偏移量与最终坐标。

> 坐标含义：`最终 = 挂点基座 + 偏移`（挂点基座来自车辆模型的 locator，偏移是你手动加的）。
> 写存档/mod 时一般用**最终坐标**；如果只想用原厂挂点、不动位置，用**挂点基座**即可。

### 界面说明

* **左栏**：车辆列表，可按「卡车 / 挂车」切换、搜索。
* **中栏**：3D 视口。左键旋转、右键平移、滚轮缩放；「复位视角」回到整车。
  点模型上的配件即可选中并用箭头调整；左下角是位置微调面板。
* **右栏**：车辆摘要（驾驶室/车身/底盘下拉切换）+ 槽位列表。
  点任意槽位打开配件选择器，里面列出**所有车辆**的同槽位配件，并标注来源车辆与原厂/改装、价格；
  已装配的槽位上有绿色「调整」标签，点它直接进入位置调整。
* **底栏**：坐标表（点任意一行也能选中该配件进行调整）。

## 技术实现

这个工具从零实现了若干 SCS 二进制格式（游戏 1.50+ 之后社区资料很少），可复用的模块如下：

| 模块 | 作用 |
| --- | --- |
| `cityhash64.py` | CityHash64（SCS 用 v1.0.3 变体），路径 → 64 位键 |
| `scs.py` | HashFS **v2** 归档读取：`SCS#` 魔数、zlib 索引、目录树、条目元数据 |
| `sii.py` | `SiiNunit` 文本定义解析（含 `attr[]` 数组、`@include`、单位引用） |
| `pmg.py` | Prism3D `.pmg` **v21** 几何：pieces / parts / **locators** / 顶点流 / 索引 |
| `pmd.py` | Prism3D `.pmd` v4 描述符：look、材质表、variant 属性 |
| `tokens.py` | SCS 8 字节 token（38 进制打包字母表）名称编解码 |
| `mat.py` | `.mat` 材质文本，提取 effect 与贴图源 |
| `texture.py` | 1.50+「纹理对象」：条目元数据 → 重建 DDS → 图片 |
| `native/` | GDeflate 解压 DLL（NVIDIA/Microsoft 参考实现，Apache-2.0，MSVC 编译） |
| `catalog.py` | 车辆/槽位/配件目录构建与本地化 |
| `model3d.py` | pmd+pmg 合并为可渲染网格，按挂点装配整车 |
| `server.py` | 本地 HTTP API（几何二进制、贴图 PNG、装配） |
| `app.py` | 桌面外壳（Chromium `--app` 窗口 / pywebview / 浏览器，逐级回退） |

### 几个关键发现

* **归档格式**：1.50+ 的 `.scs` 是 `SCS#` v2，文件名不直接可见，但归档内保存了
  **完整目录树**（每个目录一个条目）。用 CityHash64 做键即可 100% 还原文件名——
  实测 110/115 个归档可完整遍历，其中 `base.scs` 181,578 条目全部命中。
* **模板 token**：locator / part / bone 的名字是 8 字节 token，
  按 `0-9 a-z _` 的 38 进制打包（索引 0 为结束符），不是哈希，可无损解码。
* **贴图**：1.50+ 的 `.tobj` 里**只存原始 DDS 位**，宽高/mip/DXGI 格式/对齐方式全部
  挪到了归档条目的元数据里；数据用 **GDeflate** 压缩。本工具按元数据重建 DDS 头，
  再按 pitch/image 对齐剔除填充。抽样 3000 张贴图 **100% 解码成功**。
* **顶点属性是交错的**：PMG 里每个顶点占固定 `stride` 字节，位置/法线/切线/顶点色/UV
  各在自己的小偏移上。按连续数组读顶点色会得到噪声（"像贴图没加载的乱码颜色"），
  必须按 `偏移 + stride × i` 读——**这是本项目最隐蔽的一个坑**。
* **归档读必须加锁**：多个请求线程共用一个文件句柄，`seek()+read()` 不加锁会互相踩，
  表现为偶发的 `gdeflate decompression failed`（单独测那张贴图却是好的）。
* **装配规则**：配件通过挂点 locator 名称匹配槽位（精确或 `槽位_后缀`），
  例如槽位 `beacon` ↔ 挂点 `beacon_sl`，`mirror` ↔ `mirror_s`，`f_logo` ↔ `f_logo_s`；
  车轮 `f_*` ↔ `wheel_f_*`、`r_*` ↔ `wheel_r_*`（一个槽位装到每个轮位）。

## 已知限制

* 存档写入目前只到「导出坐标 + 配置」这一步：直接改 `game.sii` 需要先解密
  （社区工具 SII_Decrypt），本工具没有内置解密器。导出格式已按可写入的方式组织。
* 材质只用了 base/normal 贴图与顶点色近似 SCS 的多层着色器（金属漆、反射、发光等
  不会完全还原），因此预览是「形准、色近」，不是像素级还原。
* 内饰、动画、碰撞体不加载；挂车只加载车身+底盘+配件。
* 少数特殊 DXGI 格式（如 `r9g9b9e5`）贴图会退化为灰图。
* 不支持 `locale.scs` 以外的本地化覆盖文件；品牌名（`@@brand_xxx@@`）在游戏语言包里
  没有对应词条，因此用车型 ID 美化显示（如 `scania.s_2016` → `Scania S 2016`）。

## 目录结构

```
car-share/
├─ ETS2Garage.spec           PyInstaller 打包配置
├─ dist/ETS2Garage.exe       单文件可执行程序（约 30 MB）
├─ ets2garage/               Python 核心
├─ web/                      前端（three.js + 原生 JS/CSS）
├─ native/                   GDeflate 解压源码与编译脚本
├─ refs/                     参考实现源码（ConverterPIX / DirectStorage / libdeflate）
├─ tools/                    验证脚本（UI 自动化、格式冒烟测试、贴图抽检）
└─ docs/                     截图
```

```bat
python -m PyInstaller ETS2Garage.spec --noconfirm
```

重新编译 GDeflate DLL：

```bat
cd native && build.bat
```
